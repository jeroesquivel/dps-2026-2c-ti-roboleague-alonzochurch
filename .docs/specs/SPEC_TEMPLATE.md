## 1. Context
Why this feature exists, what problem it solves and for whom. Link relevant code or prior specs.
The agent should be able to understand the *intent*, not just the mechanics.

## 2. Functional requirements
Numbered (FR-1, FR-2, ...). What the system must do — observable behavior only, no implementation choices.

## 3. Constraints (non-functional)
Numbered (C-1, ...). Privacy, determinism, performance, or architecture rules that bound the solution.
Do not repeat AGENTS.md — only feature-specific constraints belong here.

## 4. Acceptance criteria
Given / When / Then. Each criterion must be objectively checkable — these become the test cases.

## 5. Out of scope
Explicitly excluded, so the agent does not build it.

## 6. Open questions
Anything unresolved. When an open question affects the implementation, the agent should ask — not guess.
